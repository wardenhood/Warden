Getting Started

Prerequisites

Node.js 20+Matcher requires ESM + WebSocket
FoundryContract compilation and deployment
RHC RPCHTTP (JSON-RPC) + WebSocket (eth_subscribe)
ETH on RHCEscrow deposits + gas fees

5-minute setup

# Clone + install
git clone https://github.com/wardenhood/Warden && cd Warden
cd matcher && npm install && npm run build && cd ..

# Deploy escrow contract
cd foundry && forge build
forge create --rpc-url $RHC_HTTP_URL --private-key $KEY \
  src/StreamEscrow.sol:StreamEscrow \
  --constructor-args $MATCHER_ADDRESS 100000000000000
cd ..

# Start matcher
cd matcher
RHC_WSS_URL=wss://... ESCROW_ADDRESS=0x... node dist/index.js

# Start workspace (separate terminal)
cd workspace && node server.mjs
# Open http://localhost:4000

Predicate Language

Predicates describe what on-chain events to watch. Each condition has field, op, and value. Combine with and / or.

Plain English → JSON (offline, no LLM)

$ warden ai "whales over 100k TSLA"
→ Watching Transfer events · ≥ 100,000 TSLA

JSON predicate

{
  "and": [
    { "field": "eventName", "op": "eq",  "value": "Transfer" },
    { "field": "address",   "op": "eq",  "value": "0x322F0..." },
    { "field": "value",     "op": "gte", "value": "100000000000000000000000" }
  ]
}

Operators

OpExample
eq{ field: "eventName", op: "eq", value: "Transfer" }
neqNot equal
gte / lteGreater / less than or equal (numeric, BigInt-safe)
gt / ltStrict greater / less than
in{ field: "from", op: "in", value: ["0xAAA","0xBBB"] }
not_inValue not in the given array
containsSubstring match
starts_withPrefix match
regexPattern match — sandboxed, ReDoS-protected

Nested logic

{
  "and": [
    { "field": "eventName", "op": "eq", "value": "Transfer" },
    { "field": "value", "op": "gte", "value": "1000000000000000000000" },
    { "or": [
        { "field": "from", "op": "eq", "value": "0xWhale1" },
        { "field": "from", "op": "eq", "value": "0xWhale2" }
    ]}
  ]
}
ReDoS Protection: Regex predicates validated by static heuristic (Layer 1) at registration + worker pool with 300ms timeout (Layer 2). Fail-closed.

Security

SSRF Protection (2 layers)

Layer 1 — Hostname pre-filter: Blocks literal private IPs before any request.

127.0.0.0/8All loopback addresses
10.0.0.0/8RFC1918 Class A
172.16.0.0/12RFC1918 Class B (per-octet)
192.168.0.0/16RFC1918 Class C
169.254.0.0/16Link-local + cloud metadata
100.64.0.0/10CGNAT (cloud provider internal)
fc00::/7IPv6 unique local
fe80::/10IPv6 link-local
Obfuscated IPsDecimal, hex, octal normalized

Layer 2 — DNS-pinned connection: Resolves hostname once, validates resolved IP, connects directly — no re-resolution, no DNS rebinding.

DNS resolutionExactly once per attempt
IP validationEvery address checked against blocklist
Connection pinningConnects directly to validated IP
Redirect handlingManual — each hop re-validated
Timeout10s per attempt

HMAC Signing

Every webhook carries X-Warden-Signature (SHA-256 HMAC). Verify with constant-time comparison.

XSS Prevention

All trace fields HTML-escaped via textContent before innerHTML.

ReDoS Defense

Layer 1 heuristic at registration. Layer 2 worker pool (capped, 300ms timeout). Worker cap + queue.

  eth_subscribe  StreamEscrow (Solidity)

Data flow

  1. User describes event → parser generates JSON predicate
  2. Predicate + webhook validated (SSRF) → hashed → stored on-chain via subscribe()
  3. Matcher watches RHC logs via eth_subscribe — real-time, no polling
  4. On match → broadcast SSE → deliver webhook (HMAC-signed, retried 3×)
  5. Successful delivery → recordDeliveries() (batch, up to 50/tx)
  6. Fee deducted from subscriber escrow. Receipt on-chain permanently.

Contract

StreamEscrow — deployed on Robinhood Chain (chain ID 4663).

FunctionDescription
subscribe(hash, hash)Lock ETH, register subscription. Hashes only.
recordDeliveries(ids[], hashes[])Batch receipt (up to 50/tx). Deducts fee.
cancel(subId)Deactivate, refund remaining escrow.
withdrawFees(amount)Owner withdraw. Guarded by totalEscrowed.
